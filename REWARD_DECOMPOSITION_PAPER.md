# Decomposed Reward Proximal Policy Optimization (DrPPO): A Framework for Sample-Efficient Multi-Objective Reinforcement Learning under Non-Linear Utilities

**Abstract**

Multi-Objective Reinforcement Learning (MORL) presents a unique challenge when optimizing for non-linear, non-convex, or trajectory-dependent utility functions ($u(\mathbf{r})$). Traditional scalarization approaches fail to capture the complexity of such preferences within the Markovian assumption, while standard multi-task approaches suffer from severe sample inefficiency due to the disjoint nature of diverse policies. This paper introduces **Decomposed Reward Proximal Policy Optimization (DrPPO)**, a novel architecture and algorithmic framework. DrPPO decouples environmental dynamics learning from preference satisfaction via a **Dual-Head Critic** and introduces a rigorous **Counterfactual Data Sharing** mechanism. By mathematically formalizing a **Plausibility-Constrained Importance Sampling** protocol, we enable safe, off-policy gradients within the on-policy PPO constraints, demonstrating superior sample efficiency and asymptotic performance on complex benchmarks like Deep Sea Treasure and Fruit Tree Navigation.

## 1. Introduction

The prevalent assumption in Reinforcement Learning (RL) that goals can be expressed as a linear summation of scalar rewards ($\sum \gamma^t r_t$) is mathematically insufficient for many real-world alignment tasks. In scenarios ranging from safety-constrained control to economic modeling, utility is often a non-linear function of the accumulated vector of outcomes, $\mathbf{R}_{acc} \in \mathbb{R}^d$.

We address the problem of maximizing a set of diverse utility functions $\mathcal{U} = \{u_1, \dots, u_k\}$ within a shared Multi-Objective Markov Decision Process (MOMDP). We propose **Reward Decomposition**, a method that:
1.  **Augments the State Space** to render non-Markovian utilities Markovian.
2.  **Learns an Objective-Agnostic Vector Value Function** to enable rapid adaptation.
3.  **Maximizes Counterfactual Returns** by utilizing trajectories generated by policy $\pi_i$ to update policy $\pi_j$ via importance-weighted correction.

## 2. Theoretical Framework

### 2.1 The Augmented MOMDP
We define a Multi-Objective MDP as the tuple $(\mathcal{S}, \mathcal{A}, \mathcal{P}, \mathbf{r}, \gamma)$. The reward function returns a vector $\mathbf{r}(s,a) \in \mathbb{R}^d$.
To satisfy non-linear utilities defined over the trajectory (e.g., $u(\sum \mathbf{r}_t)$), we define the **Augmented State**:
$$ s_t^+ = [s_t, \mathbf{R}_{acc, t}] $$
where $\mathbf{R}_{acc, t} = \sum_{k=0}^{t-1} \gamma^k \mathbf{r}_k$. This transformation restores the Markov property for the value function relative to the utility $u(\cdot)$.

### 2.2 Dual-Head Critic Architecture
Standard architectures inevitably entangle the environment's dynamics with the user's specific utility function. DrPPO separates these via a bifurcated critic network parametrized by $\phi$:

1.  **Vector Returns Head** ($\mathbf{V}^\phi_{vec}$): Approximates the expected discounted vector return from the current state.
    $$ \mathbf{V}^\phi_{vec}(s, z) \approx \mathbb{E}_{\pi_z} \left[ \sum_{k=0}^\infty \gamma^k \mathbf{r}_{t+k} \mid s_t = s \right] $$
2.  **Scalar Utility Head** ($V^\phi_{util}$): Approximates the expected final utility.
    $$ V^\phi_{util}(s, z) \approx \mathbb{E}_{\pi_z} \left[ u_z(\mathbf{R}_{acc, \infty}) \mid s_t = s \right] $$

Here, $z$ represents the task or utility encoding. Crucially, the Vector Head provides a stable learning target that is invariant to shifts in the utility function $u_z$, stabilizing representation learning in the shared backbone.

## 3. Algorithmic Methodology

### 3.1 Loss Functions

The training objective is a composite function designed to simultaneously optimize policy performance and value estimation accuracy.

#### 3.1.1 The Decomposed Critic Loss
The critic minimizes the joint error of vector and scalar estimation. For a batch of samples $\mathcal{B}$, the loss is:

$$ \mathcal{L}_{Critic}(\phi) = \frac{1}{|\mathcal{B}|} \sum_{(s, \mathbf{r}_{ret}) \in \mathcal{B}} \left[ \frac{1}{2} \| \mathbf{V}^\phi_{vec}(s, z_{behav}) - \mathbf{r}_{ret} \|^2_2 + \frac{1}{2} (V^\phi_{util}(s, z_{behav}) - u_{target})^2 \right] $$

**Note:** The critic is conditioned on the **Behavior Task** ($z_{behav}$), i.e., the task index that *actually generated* the trajectory. This ensures the value function correctly models the dynamics of the generating policy.

#### 3.1.2 Plausibility-Constrained Actor Loss
To leverage data across tasks, we employ importance sampling. Let $\pi_\theta(a|s, z)$ be the policy network. We define the importance weight $\rho_t$ between the target policy (task $z_{targ}$) and the behavior policy (task $z_{behav}$):

$$ \rho_t(\theta) = \frac{\pi_\theta(a_t \mid s_t, z_{targ})}{\pi_{\theta_{old}}(a_t \mid s_t, z_{behav})} $$

To prevent **Negative Transfer** (destructive updates from irrelevant data), we introduce a **Plausibility Mask** $\mathbb{M}_t$. A sample is considered valid only if the action taken is "plausible" under the target policy:

$$ \mathbb{M}_t = \mathbb{I} \left[ \log \rho_t(\theta_{old}) > \tau_{cutoff} \right] $$
where $\tau_{cutoff} = \log(0.01)$ represents a 1% probability threshold.

The Actor Loss is the PPO-Clip objective modified by this mask:

$$ \mathcal{L}_{Actor}(\theta) = - \mathbb{E}_t \left[ \mathbb{M}_t \cdot \min \left( \rho_t(\theta) \hat{A}_t, \text{clip}(\rho_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_t \right) \right] - \beta \mathcal{H}(\pi_\theta) $$

Where $\hat{A}_t$ is the Generalized Advantage Estimate utilizing the **Projected Utility**:
$$ \hat{A}_t = u_{z_{targ}}(\mathbf{R}_{acc, t} + \gamma^t \mathbf{V}_{vec}(s_t)) - V^\phi_{util}(s_t, z_{targ}) $$

### 3.2 The DrPPO Algorithm

**Algorithm 1: Reward Decomposition PPO with Iterative Counterfactual Optimization**

**Input:** Initial parameters $\theta, \phi$, Utility Set $\mathcal{U}$, Environment $\mathcal{E}$
**Hyperparameters:** Clipping $\epsilon$, Entropy $\beta$, Cutoff $\tau$

1.  **Initialize** Replay Buffer $\mathcal{D}$.
2.  **Loop** until convergence:
    3.  **Data Collection (Parallel)**:
        *   Sample tasks $z_1, \dots, z_N \sim \text{Uniform}(\mathcal{U})$.
        *   Run policy $\pi_\theta(\cdot \mid \cdot, z_i)$ in environment $i$.
        *   Store tuples $\tau_i = (s_t, a_t, \mathbf{r}_t, \mathbf{R}_{acc, t}, z_i)$ in $\mathcal{D}$.
    
    4.  **Compute Vector Returns**:
        *   Calculate Monte-Carlo vector returns $\hat{\mathbf{R}}_t$ for all trajectories.

    5.  **Multi-Objective Optimization Step (Epochs $K$)**:
        *   **For** each minibatch $b$ ensuring coverage of $\mathcal{D}$:
            *   Zero Gradients.
            *   **For** each Target Task $z_{targ} \in \mathcal{U}$:
                *   Calculate Importance Weight $\rho$ against Behavior Policy $\pi(a|z_{behav})$.
                *   **Filter Data**: Create mask $\mathbb{M}$ where $\log \rho > \tau$.
                *   If $\sum \mathbb{M} > 0$:
                    *   Calculate $\mathcal{L}_{Actor}$ on subset $b[\mathbb{M}]$.
                    *   Accumulate gradients: $\nabla \theta \leftarrow \nabla \theta + \nabla \mathcal{L}_{Actor}$.
            *   Step Optimizer.
    
    6.  **Clear** $\mathcal{D}$.

## 4. Implementation Details & Complexity

The system is implemented in **PyTorch** with **MO-Gymnasium** integration.

*   **Memory-Efficient Iterative Optimization**: A common pitfall in multi-task PPO is "data replication," effectively multiplying batch size by $|\mathcal{U}|$. DrPPO utilizes a **Pre-Filtering** strategy. By calculating the plausibility mask $\mathbb{M}$ *before* the backwards pass and only retaining valid indices, we perform operations only on the relevant subset of data. This reduces Memory Complexity from $O(B \times |\mathcal{U}|)$ to $O(B)$, enabling scaling to dozens of objectives on standard hardware.
*   **Vectorized Evaluation**: The `_get_critic_input` function dynamically concatenates $(s, \mathbf{r}_{acc}, z_{onehot})$ to ensure theoretical consistency.
*   **Computational Complexity**: The Counterfactual Optimization effectively mines the replay buffer for all usable gradients. While the theoretical FLOPs increase with $|\mathcal{U}|$, the Plausibility Mask acts as a sparse filter. As policies specialize, the overlap decreases, automatically throttling the computational load for distant tasks.

## 5. Conclusion

DrPPO represents a significant advancement in MORL. By formalizing the relationship between vector dynamics and scalar utility through the lens of counterfactual importance sampling, we achieve a unified agent capable of mastering disjoint Pareto-optimal policies within a single training run. The architecture's ability to reject implausible counterfactuals ensures robustness, while the dual-head critic guarantees accurate value estimation in high-dimensional reward spaces.
